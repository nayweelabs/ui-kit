# Web-component host and menu manifest format

## Background
Step 1 "Shared pieces" of the same-shape plan. Plan: constitution design `plan-product-shape` (steps 1-6); rules: design `global-architecture`, ADRs 1-21 (accepted 30 Oct 2026). Owner, 1 Nov 2026: same-shape stays alive (CLI first, then TUI and web UI where possible, one versioned data format).

## What
- A host in ui-kit that mounts one product web component inside the shell (ADR-12 "One UI, two hosts": the product's own shell and control-room both host it, no frame, no second UI).
- The menu manifest format: the menu entries (top menu + left menu) a product declares, and its actions (fixed command, typed arguments, destructive flag) that control-room may run (ADR-19).
- Each product keeps its own React (ADR-13); the host does not ship one.
- Documented in the README with an example manifest; preview shows a sample component in both hosts.

## Not in scope
- Any product's own component (kanban is the first, feature kanban-shape).
