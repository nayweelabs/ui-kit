#epic:constitution/confirm-changes #feature:confirm-styles

# The user picks how each type of change asks: type the name, y/N, or not at all

Plan (design plan-confirm-changes, block STYLES; owner's decision, 2 Nov 2026):

- Action types, the same words everywhere: create, edit, move, focus, archive, close, delete, settings, connect, run. Styles: `name`, `yes-no`, `never`. Default: delete = name, the rest = yes-no.
- The dialog gets a name mode: `data-ui-confirm-name="<id>"` shows "Type <id> to go ahead", and the confirm button stays off until the text matches exactly.
- `Undoable` becomes `Remember` (`data-ui-remember`): "Remember my answer" sends `confirm=remember`, in both modes, for every type.
- Go: `ConfirmName`, `Remember`, `kit.ConfirmStyle`, `Button.Ask`, and a `ui/confirm-settings` partial (one row per type, three choices, a POST form). React: the same.
- Tests (node, Go, React), preview gallery, README.
